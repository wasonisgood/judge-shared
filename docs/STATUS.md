### P1 範圍整理（標編碼標注工序）— 大部分已完成（2026-11-11）
- 已完成並驗證（在畫面上）：以「二二八事件處理及補償條例」、最多 1 筆為例，「開始整理」完成，表格有資料，訊息為「完成，共 1 筆。有 2 格待覆核」，並照實標示「網頁版尚未提供檔案保存」。耗時約 40 秒／1 筆。
- 做法：列出判決用 MCP `scope_table`；逐案全文用 MCP `get_judgment_detail`；逐案分析與綜合用核心 `analyzeCase`／`synthesizeScope`，**在瀏覽器執行**，AI 經 `aiProxy`（`apps/web/src/scope.js` 打包為 `js/scope.js`）。覆核用核心 `summarizeReview`／`applyReviewOp`（`scope.review`）。
- 已完成的匯出：Excel 與 Word（`/api/export/scope`，`format: xlsx|docx`）。Excel 每法規一個工作表，欄位值與依據分開；Word 每法規一節，含綜合分析與逐字依據。API 與下載已驗證。
- 已完成並在畫面上驗證（2026-11-11）：
  - 按鈕可用狀態（`scope.controls`，核心 `scopeUiState`）：未輸入法規時「開始整理」停用並顯示原因；有結果後匯出按鈕啟用。
  - 綜合概述、研究結論、待覆核數量（「待覆核共 4 格」）、匯出按鈕，都正確顯示。
  - 覆核的接受操作（API 層，`scope.review` 的 `op`）：待覆核的格子變為 accepted，摘要數字正確更新。
  - 依據原文（`scope.judgmentText`）：依據字串能在判決全文中找到並回傳標示範圍；找不到時回報說明。
- 剩餘（未在畫面上實測）：
  - (a) 點開「依據」彈窗，確認原文中的標示位置正確。
  - (b) 覆核的畫面操作：接受、修改、拒絕、批次接受、還原（目前只驗證了 API 層的接受）。
  - (c) 逐案分析一次一則、約 40 秒；多筆時需要數分鐘，目前沒有取消按鈕（`cancelled` 欄位未接上取消）。
  - (d) 「查看處理流程」（`scope.explain` 之類）的流程面板是否正確，尚未確認。
- 驗收（剩餘）：以「二二八事件處理及補償條例」、最多 5 筆完整跑完；點開一個依據；覆核一格（接受、修改各一次）；匯出 Excel 與 Word 並打開檢查內容。

## 3. 已知問題（目前知道的）

- 代理的回答曾寫出沒有依據的年份（國家賠償法制定年）。系統提示詞已要求只根據工具結果回答，但**尚未用同一題重新驗證**。
- 精讀的 AI 輸出有時會截斷或格式錯誤；已修補，但仍可能失敗。失敗時的訊息是「AI 回覆不是有效的 JSON」。
- 搜尋偶爾回「查無查詢結果入口（可能無結果，或遭風控）」——這是司法院網站端的回應，無法判斷是無結果還是限流。
- 網頁版的設定頁會顯示「AI 金鑰（已設定）」——這是為了符合畫面，實際由雲端與訂閱提供，不需要本機金鑰。
- 測試用的訂閱（`subscriptions/{測試帳號 uid}`，`source: manual-test`）仍存在；正式上線前需要清除或改為正式的付費流程。
